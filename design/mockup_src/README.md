# Mock-up sources

Python scripts that generate the HTML mock-ups in `design/html_mockups/`. They import each other, so keep them in one folder and run from it.

Paths inside the scripts point to `/home/claude/` (input) and `/mnt/user-data/outputs/` (output) from the Claude session that wrote them; change those two paths to run them elsewhere.

| Script | Builds |
| --- | --- |
| `build_week.py` | Calendar week board draft (`draft-week-board.html`). Also holds the shared base CSS, icons and card helpers. `v13.css` is the original approved mock-up CSS it loads. |
| `build_area2.py`, `build_area4.py` | Shared parts for the area screen (sidebar, cards, timeline, agenda, routines). |
| `build_overview.py`, `build_overview2.py`, `build_overview3.py` | Life areas overview (approved). `build_overview3.py` is the final one. |
| `build_area5.py` | Area screen (approved). |
| `build_project2.py` | Project screen, normal state (presentation rules applied). |
| `build_project_states.py` | Project screen with all mock states (`approved-project.html`). |
| `build_projects_overview.py` | Projects overview with all mock states (`approved-projects-overview.html`): stat tiles with mini line charts, timeline with a Next up card beside it, and a projects board (no pace) with Group by, Sort by and Show finished in its card menu. Imports `build_empty.py`, `rules.py`. |
| `build_empty.py` | Shared parts for the Life areas overview empty states and the New area pop-up (now part of `approved-areas-overview.html`). |
| `build_area_states.py` | Area screen with all mock states (`approved-area.html`). |
| `build_overview_states.py` | Life areas overview with all mock states (`approved-areas-overview.html`). |
| `rules.py` | Shared presentation rules applied to every approved screen (data-only subtitles, no guide text, sort-and-filter menus, spacing) and the consistency pass (one Areas-group sidebar with LIFE AREAS, PROJECTS and Archived; no Notes tab in the tabbed card), stored palette names on color pickers, and reordering areas by dragging in the sidebar (no Reorder areas pop-up). Since Nov 14 (night) it also holds the create-form rules (`forms()`: no "optional" tags, disabled Create, the New metric pop-up with Source, Measure as and Current value, its Measure as menu, routine-step and Delete metric states) and Delete in the detail panel's ⋯ menu. `rules.apply()` is idempotent, so it can also be run on a finished approved file. |
| `build_panel.py` | Detail panel with all states (`approved-detail-panel.html`), shown over the projects overview. Also imported by `build_area_states.py` and `build_project_states.py` for their Edit (side panel) states. Reads `approved-projects-overview.html`. |
| `build_pickers.py` | Pickers, approved (`approved-pickers.html`): every picker opened from the chip or field it belongs to, over the detail panel (due, typing a date, scheduled, date range, event time, event over several days, repeat, custom repeat, priority, owner, section, period) and the New metric pop-up (routine step). Reads `approved-detail-panel.html` and `approved-area.html` (paths are arguments), imports `rules.py`.. Since Nov 15 (Phase D) the date picker is the one from Approved: Tasks: the date field, Today / Tomorrow / Next week as three icon buttons (date on hover), then the month; no "Unscheduled" row (the due picker keeps "No due date"). |
| `build_calendar.py` | Calendar screen, all four views approved Nov 15 (`approved-calendar.html`): Week's 18 states plus 14 Month, 8 Quarter and 6 Year states; the mock-state bar has a View switch, and the header's Week / Month / Quarter / Year switch jumps between views. Since the Nov 15 review: day entries fill the free lines beside range bars (Week and Month), cells fit their content with a small script on load and resize ("+n more" in Month, "+n" marks in Quarter / Year), times on the hour drop ":00" (`short_times()`), and the sidebar's SHOW list follows the view (Quarter / Year: Projects instead of Routine steps and Project due dates). Usage: `python build_calendar.py <approved-detail-panel.html> <approved-area.html> <out.html>`. |
| `build_cal_views.py` | Month (FullCalendar day grid: bars per week row, routine ring beside the date, "+3 more" day popover) and Quarter / Year (linear calendar: one row per month, 37 weekday slots, event and project bars, single-day marks, Year keeps 3 lanes with "+n"), their agenda, period pickers, drag states and CSS. Imported by `build_calendar.py`. |
| `cal_data.py` | Mock data for Month, Quarter and Year: one year (2026) of events, bars, projects (start to due), routines and tasks. Nov 9 – 15 comes from `build_next7.week()`, Oct 26 – Dec 6 is written by hand, the rest is seeded. |
| `build_cal_week.py` | Helpers used by `build_calendar.py` (day entries, ordering, New event, event panel). Its own output, `draft-week.html`, is outdated. |
| `build_next7.py` | Untimed day board (`draft-next-7-days.html`): Unscheduled + Mon–Sun Kanban columns with the cards from `docs/All - Area.png`. Built Nov 15 as the week board; its own output is outdated (Next 7 days now lives in `approved-tasks.html`). Still imported by `build_calendar.py` and `build_tasks.py` for icons, mock data and helpers, so keep it. |
| `build_tasks.py` | Tasks group, approved Nov 15 (`approved-tasks.html`): one file with every Tasks screen and 28 mock states — All (Priority and Area groups), Today (Overdue subgroup), Inbox with a right panel switched between Areas (areas with their projects), Calendar (month grid, drop on a date) and Priority (four cards), Next 7 days (rolling from today, No date + 7 day columns, multi-day items repeated on each day, Area or Priority subgroups), Routines (one board, a column per routine), Projects, a project (Section group), Completed, Cancelled, Archived; the filter-and-sort menu, New task (empty, filled, with a picker), the detail panel, the dark undo toast, drag states and empty states. Columns are one fifth of the board wide (fewer groups leave space empty). Applies the placement rule (scheduled date, else due date with a Due chip, else Unscheduled). Reads `approved-detail-panel.html` and `approved-area.html`; imports `build_next7.py`, `build_pickers.py`, `rules.py`. |
| `build_routine.py` | Routine screen, approved Nov 15 (`approved-routine.html`, Phase E): the Areas sidebar with a ROUTINES group, the routine page (stat tiles, Steps heatmap with an All steps row, Completion by step, Schedule history, Day card) in Week, Month, Quarter and Year, and 21 mock states (past day, day popover, skip + undo toast, not due today, paused, new routine with and without steps, no routines, ⋯ menu, Add step, New routine, editing a step in place, schedule picker, Change schedule, Delete routine, drag to reorder; no detail panel for routines or steps). Checkboxes, Skip, Skip day, clicking a day and the period switch work. Reads `approved-area.html`, `approved-project.html`, `approved-projects-overview.html` and `approved-tasks.html`. Usage: `python build_routine.py <html_mockups dir> <out.html>`. |
| `build_routines_overview.py` | Routines overview, approved Nov 15 (`approved-routines-overview.html`, Phase E), opened from the ROUTINES heading: five stat tiles across all routines, a Routines heatmap (one row per routine, shaded by the share of steps done), Completion by routine, and a Slipping card (Open today, Most missed, Streaks ended this week); 9 mock states (Quarter, Week, Month, Year, card menu, ⋯ menu, New routine, routines with no history, no routines). Imports `build_routine.py`. Usage: `python build_routines_overview.py <html_mockups dir> <out.html>`. |
| `build_home.py` | Home, approved Nov 15 (`approved-home.html`, Phase F): no context sidebar, no period switch. Header with the date, a data line (done count, next item), quick add (Enter = task scheduled today, no owner) and the New split button (Task, Event, Metric entry). Today card (the approved agenda rows for today: Overdue, Schedule with a now line, Tasks, Completed collapsed; row hover actions Tomorrow and Pick date), Routines today (one Day-card block per routine due today; all-done routines collapse), Log today (manual metrics with a per-day or per-week target, inline value field), Needs a push (Inbox count, Projects, Routines streaks ended, Metrics behind) and Coming up (next 7 days, fixed-date items only). 17 mock states; checkboxes, Skip, subtasks, quick add, logging, Tomorrow, the New menu and the undo toast work. Reads `approved-calendar.html`, `approved-projects-overview.html`, `approved-tasks.html`; imports `build_routine.py`, `build_routines_overview.py`. Usage: `python build_home.py <html_mockups dir> <out.html>`. |
| `build_confirmations.py` | Confirmations, approved Nov 15 (`approved-confirmations.html`, Phase G): one 480 px dialog for every confirmation that lists what goes with an action (Archive area; Complete, Cancel and Archive project; Archive routine; Delete routine, recurring task, event, area). Groups by effect (Cancelled, Ends from today, Archived, Deleted, Kept, Stops updating) with caps labels and counters, entity rows, "+n more" (folds only when 2+ rows would hide), a scrolling list with scroll shadows, a choice slot for repeating events, footer data line, Go back and the named action (red only for Delete). 17 mock states over the approved project page; "+n more", the event choices, Go back and the confirm toast work. Reads `approved-project.html`. Usage: `python build_confirmations.py <html_mockups dir> <out.html>`. |
| `build_settings.py` | Settings, approved Nov 15 (`approved-settings.html`, Phase G step 1): the rail with Settings active, a context sidebar listing General, Data and About (clicking scrolls to the card), and a 720 px column of section cards with label-left, control-right rows and muted data lines (red for problems). General: Open on start, Time format, Day ends at, Reset layout. Data: Automatic backups, Keep last, Backup folder, Last backup with Back up now, Export all data. About: Version, Database. The page is drawn by one script from a state object, so every control works (segmented groups, switch, selects, Back up now, Retry, Reset with the undo toast, Export toast) and 24-hour changes every time shown. 10 mock states. Reads `approved-home.html` (base CSS, rail, toast); does not run `rules.apply()`. Usage: `python build_settings.py <html_mockups dir> <out.html>`. |
| `build_archived.py` | Archived, approved Nov 15 (`approved-archived.html`, Phase G step 2): the Areas sidebar with Archived active, a header with the Areas / Projects / Routines switch (grey counters) and a filter icon on Projects, and one 960 px list card (projects grouped Done, Cancelled, Archived). Rows show Restore or Reopen and ⋯ on hover; Restore, Reopen, Archive, Undo, Delete (approved confirm dialog), the detail panels (read-only, ⋯ holds Restore), the filter menu and the read-only archived routine page all work. 16 mock states. Imports `build_routine.py` (shell, sidebar, routine page, CSS and JS; the archived routine is `R_ARC`) and `build_confirmations.py` (`row()`, `group()`, `dialog()`); reads `approved-area.html`, `approved-project.html`, `approved-projects-overview.html` and `approved-tasks.html`. Does not run `rules.apply()`. Usage: `python build_archived.py <html_mockups dir> <out.html>`. |
| `review_fixes.py` | Phase 2 quick wins from the UX review (Nov 16): post-processes every `approved-*.html` into `draft-*.html` (drops ":00" on 12-hour times, adds the ROUTINES group to the Areas sidebar, renames Archived to Finished & archived, Effort fills and area Add buttons in the 700 shade, done text #6b7280, disabled buttons at 55%, today marker brand 700, 11 px chart labels, the routine key on the routine page and Routines overview, the detail panel's ×, "Due Nov 4" chip, toast wording, "Until 3 PM", agenda opening at today). Usage: `python review_fixes.py <html_mockups dir> <out dir>`. |
| `review_fixes2.py` | Nov 16, before the Claude Code handoff: neutral accent (primary buttons and checkboxes neutral; brand purple kept for the rail, pickers' selection, the selected-row marker, focus and today) and plain priority names (High, Medium, Low, No priority; Eisenhower names removed from Tasks columns and the Priority picker). Reads `approved-*.html`, writes `draft-*.html`. Usage: `python review_fixes2.py <html_mockups dir> <out dir>`. |

`rules.py` also holds, since Nov 15, `neutral_text()`: text never takes area colours (titles, metadata, timeline labels, area tags); area colour stays on markers, icons, edges, fills and tints. It runs inside `forms()`, so `rules.apply()` covers it.
